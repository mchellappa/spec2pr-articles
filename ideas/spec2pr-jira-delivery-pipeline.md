# Spec2PR: How a Jira Ticket Became the Start of an Entire Delivery Pipeline

Audience: Engineering leaders, delivery managers, and senior engineers working in multi-team environments
Tone: Practical and systems-thinking — connecting planning artifacts to delivery intelligence

A Jira ticket is where engineering intent is first captured. It is also where most of
that intent gets lost before it reaches implementation. The Spec2PR Jira analysis feature
in the DevEx AI Assistant extension changes that — detecting whether a story spans
multiple repositories, generating coordination plans with phases and dependencies,
mapping service ownership, and creating the full implementation context before a single
line of code is written.

Key points:
- How single-repo vs multi-repo story detection works and why it matters for planning
- The coordination plan: phases, dependencies, subtask breakdown from one Jira ticket
- How the extension learns your repo structure and gets smarter with each story
- Why starting delivery planning from the Jira ticket (not the LLD) reduces missed dependencies
- How the .devex knowledge folder turns individual analysis into team engineering memory
